# ⚠️ 运行时升级纪律（真实事故教训，2026-09-15）

## 事故

用户正在运行旧版 dsh-desktop.exe（guard ≤0.1.5），AI 直接执行了
`npm install -g @deepseek-ai/dsh@0.1.6-alpha.1 --prefix <runtime root>`
导致运行时热替换，旧壳启动预检拦截（guard ≤0.1.5 < 0.1.6）→ 应用打不开。
用户被迫动用另一个 Agent 修复。**同类事故发生了两次。**

## 铁律（违反 = 事故）

1. **运行时升级必须在用户确认「应用已关闭」之后执行。**
   绝不在应用可能正在运行时执行 `npm install -g @deepseek-ai/dsh@...`。
2. **改任何仓库代码前必须 `git pull` 并阅读远程新提交**（至少一次真实事故：
   推送被拒后盲目 rebase，未读远程提交内容）。
3. **宣布"完成/修复"必须附运行时实证**（进程存活、端点探测、日志行），
   不靠推断——harness 工具进程的环境变量会被剥离，探测结果可能与实际不符。

## 正确流程

```
① 改源码（guard bump 等）
② cargo build --release
③ 告诉用户：请关闭应用，关闭后告诉我
④ 用户确认关闭后：执行 npm install（运行时升级）
⑤ 用户启动新 exe
⑥ 验证（进程存活 + 功能冒烟）
```

## 为什么写在这里

任何未来修改 install.rs / 升级运行时 / 触碰 remote_account.rs 的 Agent，
**必须在动手前读本文件**。
